# 子どもの再ログイン（キャラクター復帰）機能

**日時:** 2026-03-11

## 問題
匿名認証のセッションはブラウザ/デバイスに紐づくため、別のブラウザや端末からアクセスすると以前のキャラクター（例: りゅうくん）でログインできず、新規作成になってしまう。

## 解決アプローチ
ファミリーコードを使って既存の子どもキャラクターを検索し、新しい匿名セッションを既存ユーザーに紐付ける「復帰フロー」を追加。

## 修正内容

### 新規: `src/app/api/auth/child-rejoin/route.ts`
- **POST**: ファミリーコードから子どもの一覧を取得（レベル・モンスター絵文字付き）
- **PUT**: 既存の子どもとして復帰（新しい匿名セッションの `supabaseId` を既存ユーザーに上書き）

### 変更: `src/app/child/onboarding/page.tsx`
- オンボーディングフローにステップ追加:
  1. `welcome` → ようこそ画面（変更なし）
  2. `family-code` → **新規** ファミリーコード入力画面
  3. `select-child` → **新規** 既存キャラクター選択画面（復帰フロー）
  4. `name` → 名前入力（新規キャラ作成フロー）
  5. `side` → サイド選択（変更なし）
  6. `result` → 結果画面（変更なし）
- 復帰フロー: コード入力 → 既存キャラ一覧表示 → タップで復帰 → クエスト画面へ
- 新規フロー: コード入力（or スキップ） → 名前 → サイド → 結果 → クエスト画面へ
- 「コードなしではじめる」オプションも用意（ファミリー未参加でも開始可能）

## フロー図
```
welcome
  ↓
family-code ──(コードなし)──→ name → side → result → /child/quests
  ↓
  ├─(既存の子あり)→ select-child → /child/quests (復帰)
  │                    └─(あたらしく作る)→ name → side → result
  └─(子なし)→ name → side → result → /child/quests (新規)
```

## テスト方法
1. 親アカウントでファミリーコードを確認
2. シークレットウィンドウで `/child/onboarding` にアクセス
3. ファミリーコード入力 → 既存キャラ（例: りゅうくん）が表示される
4. キャラクターをタップ → クエスト画面に復帰
