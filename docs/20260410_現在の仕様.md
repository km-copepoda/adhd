# QuestBoard — 現在の仕様書（2026-04-10 時点）

## 1. プロジェクト概要

**QuestBoard** は、ADHDの子どもを主な対象とした、ゲーミフィケーション型タスク管理アプリケーション。日常のタスク（家事・勉強・運動など）をRPG風のクエストに変換し、モンスター育成・進化・転生・図鑑コレクション・実績バッジといったゲーム要素で習慣形成をサポートする。

### コンセプト
- 子どもがクエスト（タスク）を完了 → XPを獲得 → モンスターが進化 → 転生してコレクション
- 親がタスク管理と承認を担当、子どもは自律的にクエストに取り組む
- ADHD特性に配慮した設計（即時フィードバック、短いサイクル、スキップの許容）

### ポジショニング（2026-04-04 決定）
- 「習慣デザイン × ゲーミフィケーション」を前面に、ADHD支援は副次的な訴求
- 理由：より広いマーケットへのアピール

## 3. 認証・ユーザーロール

### 親（PARENT）
- **認証方式**: メールアドレス + パスワード（Supabase Auth）
- **初回登録時**: Family が自動作成され、6桁のファミリーコードが発行される
- **ログイン後**: `/app/parent/tasks` へ遷移

### 子ども（CHILD）
- **認証方式**: ファミリーコード + ユーザーコード（4桁）による匿名ログイン
- **アカウント作成**: 親がファミリー管理画面で子どもの名前と DARK/LIGHT スタイルを設定して作成
- **ログイン後**: `/app/child/quests` へ遷移

### ロール判定（ミドルウェア）
- メールアドレスあり → PARENT
- メールアドレスなし（匿名） → CHILD

## 6. コアゲームメカニクス

### 6.1 モンスター進化システム

#### 進化段階
| ステージ | 名称 | 必要ポイント |
|---------|------|-------------|
| 0 | 卵 | 初回: 1pt で孵化 / 転生後: 5pt で孵化 |
| 1 | 第1形態 | 10pt で進化 |
| 2 | 第2形態 | 30pt で進化 |
| 3 | 最終形態 | 20pt で転生可能 |

- 1サイクル: 約61pt（1日7ptペースで約8〜10日、5ptペースで約12日）

#### 進化パス選択
- 各進化時に STUDY / STAMINA / LIFE の3方向から重み付きランダムで決定
- 各カテゴリの蓄積XPに比例した確率（最大60%キャップ）
- 卵ボーナス: 転生時に選択したカテゴリに+20%の確率上昇

#### モンスター種類
- 第1形態: 3種 × 第2形態: 9種 × 第3形態: 27種 = **39種**
- DARK / LIGHT の2スタイル: **39種 × 2 + 卵1 = 79種コレクション**
- 各モンスターに名前・画像・説明文あり

#### 転生サイクル
1. 最終形態で20pt到達 → `rebirthPending = true`
2. 子どもが転生ボタンを押す → 卵タイプ（STUDY/STAMINA/LIFE）を選択
3. XP全リセット、ステージ0に戻る
4. 前回の進化パスが `collectedPaths` に記録、`monsterLevels` がインクリメント
5. 選択した卵タイプで次サイクルの進化確率にボーナス

### 6.2 XP（経験値）システム

#### 獲得ポイント（フラットモデル）
| 条件 | XP |
|------|-----|
| タスク完了（基本） | +1pt |
| 締め切りボーナス（reportDeadlineTime前に報告） | +1pt |
| 写真ボーナス（photoBonus=true かつ写真添付） | +1pt |
| **1タスクあたり最大** | **3pt** |

#### XP配分
- STUDY タスク → `studyPt` に加算
- STAMINA タスク → `staminaPt` に加算
- LIFE タスク → `lifePt` に加算
- ストリークボーナス等 → 3カテゴリに均等配分（余りは STUDY へ）

**重要**: XPは承認時にのみ付与される（報告時ではない）

### 6.3 クエストのステータスフロー

```
PENDING → REPORTED（子どもが完了報告）→ APPROVED（親が承認、XP付与）
                                       → REJECTED（親がリジェクト）
PENDING → SKIP_REPORTED（子どもがスキップ申請）→ SKIPPED（親が承認、XPなし）
```

- **スキップ**: XPは付与されないが、日次ストリークにはカウントされる（ADHD配慮：できない日を正直に申告することを評価）
- **リジェクト**: タスクテンプレートの問題として扱い、再報告の機会を与える

### 6.4 タスクの種類

#### 定期タスク
- `isTemporary = false`
- `repeatDays` で曜日指定（例: [1,3,5] = 月水金）

#### 一時タスク
- `isTemporary = true`
- `targetDate` で特定日を指定

#### 子ども作成タスク
- `createdBy = "CHILD"` で作成
- 親の承認キューに表示される
- 親が承認すると `createdBy = "PARENT"` に変更されて正式なタスクになる
- 子どもの自律性を促進する設計

### 6.5 自動承認

- **Vercel Cron ジョブ**: 毎日 15:00 UTC（= 00:00 JST）に実行
- `POST /api/cron/auto-approve`（`CRON_SECRET` で保護）
- 前日の REPORTED / SKIP_REPORTED を自動承認
- **理由**: ADHD の子どもにとって承認の遅延はモチベーション低下に直結するため

### 6.6 ストリークシステム

#### 日次達成ストリーク
- 1日1つ以上の APPROVED/SKIPPED クエストがあればカウント
- マイルストーンボーナス: 3日(+5pt) / 7日(+10pt) / 30日(+20pt) / 100日(+30pt)

#### ログインストリーク
- アプリを開いた日をカウント（タスク完了は不要）
- 10日連続ごとに +1pt ボーナス（最低XPのカテゴリに付与）
- 「アプリを開く習慣」自体をADHD支援として評価

#### タスク別ストリーク
- タスクごと・子どもごとに連続達成日数を追跡
- `TaskStreak` テーブルで管理

### 6.7 実績バッジシステム（100種）

#### バッジカテゴリ
| 範囲 | カテゴリ | 例 |
|------|---------|-----|
| #1-10 | 初めての達成 | 初孵化、初クエスト、初写真、初進化など |
| #11-16 | タスクストリーク | 3/7/14/21/30日連続、カムバック |
| #17-21 | ログインストリーク | 3/7/14/30日連続、朝の報告 |
| #22-27 | クエスト数 | 10/30/50/100/200/300回 |
| #28-32 | 承認数 | 10/30/50/100/200回 |
| #33-37 | XPマイルストーン | 10/30/50/100/200pt |
| #38-41 | 写真添付 | 5/20/50/100枚 |
| #42-45 | 締め切りボーナス | 初回、10/30/50回 |
| #46-51 | 時間帯達成 | 朝/午後/素早い報告 |
| #52-56 | 1日パーフェクト | 初回、5/15回、1日3/5クエスト |
| #57-60 | 週間達成 | 5日以上×1/3回、7日×1/3回 |
| #61-64 | 月間達成 | 10/15/20日以上、パーフェクト月 |
| #65-69 | 転生マイルストーン | 1/2/3/5/7回転生 |
| #70-75 | コレクション | 3/6種、全タイプマスター |
| #76-83 | 自発的達成 | 自作タスク、習慣ストリーク、カムバック |
| #84-91 | 季節・時期 | 月曜、週末、春夏秋冬、年末年始 |
| #92-100 | 複合チャレンジ | マイルストーン同時解除、トリプルクラウンなど |

- タスク承認時およびログインストリークチェック時に `checkAndUnlockBadges()` で判定
- fire-and-forget パターン（バッジ処理の失敗が承認をブロックしない）

## 8. プッシュ通知・リアルタイム

### 2層戦略
1. **アプリ表示中**: Supabase Realtime で即座に反映（OS通知なし）
2. **アプリ非表示/閉じている時**: Web Push API で OS通知

### 通知トリガー
- 子どもがタスク作成 → 親に通知
- 子どもがクエスト完了報告 → 親に通知
- 子どもがスキップ申請 → 親に通知
- 親が手動リマインダー送信 → 子どもに通知

### 技術実装
- VAPID 鍵ペアによる署名
- Service Worker がアプリの可視状態を `clients.matchAll()` で判定
- `PushSubscription` テーブルでデバイス管理
- 期限切れ（410）のサブスクリプションは自動クリーンアップ

## 11. 日付・時間の取り扱い

- **すべての日付計算はJST（日本標準時）** で行う
- `src/lib/date.ts` に JST ユーティリティを集約
  - `todayJST()`: JST での今日の日付
  - `dayOfWeekJST()`: JST での曜日
  - `monthStartJST()` / `monthEndJST()`: 月の境界
  - `todayRangeJST()`: 今日の24時間 UTC レンジ
  - `isBeforeDeadline()`: 締め切り判定
- **理由**: Vercel（UTC）と利用者（JST）の不一致によるバグ防止
