## 1. コンセプト・ターゲット

### アプリの一言説明
小学校高学年〜中学生のADHD傾向を持つ子どもが、自分だけのモンスターを育てながら日々のタスクをこなすRPG型タスク管理アプリ。親の承認がゲームに自然に組み込まれている。

### ターゲット

| 対象 | 詳細 |
|------|------|
| プライマリ | 小学校高学年〜中学生（10〜15歳、ADHD傾向あり） |
| セカンダリ | その保護者（承認者・課金者） |
| βテストユーザー | 自分の子ども（13歳）＋友達の子ども（5家族以内） |
| 将来的に | 学校・塾・特別支援クラス（B2B展開） |

### ADHDの特性と設計方針

| ADHDの特性 | 設計での対応 |
|------------|-------------|
| 即時報酬が必要 | タスク完了の瞬間にパラメータがリアルタイムで仮反映 |
| 外部締め切りに強い | 親という承認者が動機づけになる |
| 長期目標が続かない | モンスターの進化・ストリークが継続の引力 |
| ネガティブなセルフイメージ | 「修行しているモンスター」として自己イメージを書き換える |
| 喪失感に弱い | ストリークが途切れても過去の記録は絶対に消えない |

## 3. パラメータシステム

### 3パラメータの定義

| パラメータ | 対応タスク例 | 進化への影響 |
|------------|-------------|-------------|
| 📚 学力 | 宿題・読書・勉強・塾など | 学力50%以上 → 魔術師・賢者系 |
| 💪 体力 | 運動・お風呂・早寝・部活など | 体力50%以上 → 戦士・魔剣士系 |
| 🌿 生活力 | 片付け・お手伝い・食事・早起きなど | 生活力50%以上 → 自然・精霊系 |

### レベル計算
- 学力 ＋ 体力 ＋ 生活力 の合計値 ÷ 10 = レベル（小数点切り捨て）
- 例：学力48 ＋ 体力24 ＋ 生活力18 = 合計90 → Lv.9

### 進化タイミングと進化先

| 状態 | 条件 | 内容 |
|------|------|------|
| 🥚 たまご | スタート時 | まだ何もしていない状態 |
| 🐣 Lv1 孵化 | 合計10pt | 初日に必ず体験できる最初の成功体験 |
| 👾 Lv3 初回進化 | 合計30pt（約1ヶ月） | パラメータの割合で進化先が分岐 |
| 🧿 Lv7 2回目進化 | 合計70pt | より個性が出る中間形態 |
| 😈 Lv15 最終進化 | 合計150pt | 各系統の最強形態 |

### 進化先の決定

| 割合の傾向 | 進化先（ダークサイド🌑） | 進化先（ライトサイド🌸） |
|------------|------------------------|------------------------|
| 学力50%以上 | 🧙 魔術師・賢者系 | 🦉 賢者・星系 |
| 体力50%以上 | 💀 魔剣士・鬼将軍系 | 🐯 元気・炎系 |
| 生活力50%以上 | 🐺 森の魔王系 | 🦊 妖精・花系 |
| 3つ均等（各25〜40%） | 👑 真の魔王（隠し進化） | 🌟 虹色の精霊（隠し進化） |

※ 進化先は進化タイミング時点の過去30日間パラメータ割合（スナップショット方式）で決まる。

> 🔮 将来仕様：同一系統に3回進化した場合、特別な「極意進化」形態に変化する。特化型のADHDの子どもが自分の強みを肯定できる設計。βテストで各パラメータの偏り傾向を確認してから具体設計する。

## 6. ストリーク設計

### モンスターのストリーク

| 項目 | 仕様 |
|------|------|
| 達成条件 | 定期タスクを1個以上こなす（親に承認してもらう） |
| 途切れたとき | 現在のストリークはリセット。過去の記録・最高記録は残る |
| 表示する数値 | 現在の連続日数 ／ 今月の達成日数 ／ 最高記録 |
| 休息券 | 週1回使えるノーカウント日（途切れを防ぐ） |

### ストリークの報酬

| 連続日数 | 称号 | ボーナスpt |
|---------|------|----------|
| 3日連続 | 「はじめの一歩」🔥 | +5pt |
| 7日連続 | 「一週間の戦士」⚔️ | +10pt |
| 30日連続 | 「月の修行者」🌙 | +20pt |
| 100日連続 | 「伝説の冒険者」👑 | +30pt |

## 8. 親子のUXフロー

### 子どもの1日の流れ
1. 朝：アプリを開く → 今日のクエスト確認
2. 日中：タスクをこなして完了申告 → パラメータが仮反映
3. 夜：親が承認 → パラメータ確定 → モンスターが光る演出

### 親のUX設計
**「親がめんどくさいと感じた瞬間、アプリは死ぬ」。承認フローは1タップで完結。**

| 機能 | 設計方針 |
|------|---------|
| 承認画面 | タスク一覧 ＋「まとめて全承認」ボタンが最重要 |
| 差し戻し | やさしいテンプレートコメント必須（「却下」「失敗」は使わない） |
| タスク管理 | Webで管理（スマホブラウザ対応） |
| 通知 | メール通知 or 夜にWebを開いて確認（プッシュ通知はフェーズ2） |

### タスク締め切りと自動承認

| 項目 | 仕様 |
|------|------|
| タスク締め切り時刻 | 親が家族ごとに設定（デフォルト21時） |
| 自動承認タイミング | タスク締め切りから2時間後 |
| 子どもへの結果反映 | 翌朝アプリを開いたときにバナー表示（通知なし・アプリ内のみ） |
| 親への通知 | メール通知（承認忘れ防止） |

**設計の理由：** 時刻固定にすると家庭の生活リズムに合わない。早寝の家庭は20時、夜型の家庭は23時など柔軟に設定できることで、親の承認負荷を下げる。ADHDの子どもが締め切りに間に合わなかった日も「自動承認される」安心感が継続率を守る。

## 9. アカウント・認証設計

| ステップ | 内容 |
|---------|------|
| Step1 | 親がアカウントを作成（メール ＋ パスワード） |
| Step2 | 6桁の家族コードが発行される |
| Step3 | 子どもがアプリを開いて家族コードを入力 |
| Step4 | 子ども用アカウントが親アカウントに紐付けられる |
| Step5 | サイド選択（ダーク🌑 / ライト🌸）→ モンスター表示 |

### Supabaseでの実装方針
- familiesテーブルに invite_code カラムを持たせる
- 子どものusersレコードにfamily_idを持たせて紐付け
- RLSで「同じfamily_idのデータのみアクセス可能」に制限

### 13歳未満問題
MVPは後回し。βテストは知人・家族からスタートのため実害はほぼゼロ。App Store / Google Playのストア公開前に保護者同意フローを実装する。

## 10. 技術スタック

| レイヤー | 技術 | 理由 |
|---------|------|------|
| Web（親・子ども） | Next.js (App Router) + Vercel | 即デプロイ・一人開発に最適 |
| DB・認証・リアルタイム | Supabase | Auth・Realtime・Storageが全部入り |
| リアルタイム反映 | Supabase Realtime | 承認→即座に子ども画面に反映 |
| メール通知 | Supabase Edge Functions + Resend | シンプルに実装可能 |
| モバイル（フェーズ2） | Expo (React Native) | Next.jsと知識共有 |
| プッシュ通知（フェーズ2） | Expo Push Notifications | iOS/Android両対応 |

### DBスキーマ（概略）
- families（家族グループ・家族コード）
- users（親・子どもアカウント・サイド選択）
- tasks（定期タスク）
- completions（完了申告）
- approvals（承認・差し戻し）
- parameters（学力・体力・生活力の累計）
- streaks（ストリーク記録）

### ⚠️ 絶対に削ってはいけないもの
**「承認したら即座に子どもの画面に反映される」リアルタイム性**

## 14. 主要リスクと対策

| リスク | 内容 | 対策 |
|--------|------|------|
| 親承認サボり | 子どもが頑張っても親が承認しない | 仮承認＋24時間自動承認 |
| 子どもがアプリを開かない | ゲーム要素が刺さらず離脱 | モンスターへの愛着設計・ストリーク |
| 作りすぎて詰む | MVPに機能を詰め込みすぎる | 7画面以上作らない |
| ビジュアルクオリティ不足 | モンスターが魅力的でなく継続しない | AI生成・フリー素材で早期に検証 |
| 効果なくて解約 | 継続率が上がらず親が解約 | 週次レポートで子どもの成長を可視化（フェーズ2） |
