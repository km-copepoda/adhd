## 1. βテストで検証すること（2段階）

### なぜ2段階か
ADHDの特性として「熱しやすく冷めやすい」ため、ズルや離脱は慣れてきた頃（1ヶ月以降）に起きる。最初から全部を検証しようとするとMVPが肥大化する。

### フェーズA：〜2週間「そもそも毎日開くか」
**仮説：モンスターへの愛着が、毎日アプリを開く動機になるか**

| 計測指標 | 目標値（仮） |
|---------|------------|
| DAU（毎日起動） | 5家族中4家族 |
| タスク完了申告率 | 50%以上 |
| モンスター図鑑の閲覧回数 | 1日1回以上 |

フェーズAで「そもそも開かない」なら、フェーズB以降は無意味。ゲーム要素を作り直す。

### フェーズB：〜1ヶ月「親の承認フローが機能するか」
**仮説：親が毎日承認することで、子どものタスク継続率が上がるか**

| 計測指標 | 目標値（仮） |
|---------|------------|
| 親の承認率（自動承認されずに手動承認） | 70%以上 |
| 子どもの承認待ちによる離脱 | 観察 |
| 承認後の子どもの反応（モンスターが光る演出への反応） | 定性ヒアリング |

### フェーズC：1ヶ月以降「ズル防止が機能するか」
**仮説：親の承認＋写真添付が、Habiticaで起きたようなズルを防いでいるか**

| 計測指標 | 確認方法 |
|---------|---------|
| 写真なし承認の頻度 | ログ確認 |
| タスク内容の妥当性 | 親へのヒアリング |
| 子どもの「やってないのにやった」申告 | 親へのヒアリング |

## 2. コンセプト・ターゲット

### アプリの一言説明
小学校高学年〜中学生のADHD傾向を持つ子どもが、自分だけのモンスターを育てながら日々のタスクをこなすRPG型タスク管理アプリ。親の承認がゲームに自然に組み込まれている。

### ターゲット

| 対象 | 詳細 |
|------|------|
| プライマリ | 小学校高学年〜中学生（10〜15歳、ADHD傾向あり） |
| セカンダリ | その保護者（承認者・課金者） |
| βテストユーザー | 自分の子ども（13歳）＋友達の子ども（5家族以内） |
| 将来的に | 学校・塾・特別支援クラス（B2B展開） |

### ADHDの特性と設計方針

| ADHDの特性 | 設計での対応 |
|------------|-------------|
| 即時報酬が必要 | タスク完了の瞬間にパラメータがリアルタイムで仮反映 |
| 外部締め切りに強い | 親という承認者が動機づけになる |
| 熱しやすく冷めやすい | 2段階βテストで離脱タイミングを観察・対策する |
| 長期目標が続かない | モンスターの進化・ストリークが継続の引力 |
| ネガティブなセルフイメージ | 「修行しているモンスター」として自己イメージを書き換える |
| 喪失感に弱い | ストリークが途切れても過去の記録は絶対に消えない |
| 衝動的なズル（Habitica問題） | 親の承認＋写真添付で抜け穴を塞ぐ |

## 3. パラメータシステム

### 3パラメータの定義

| パラメータ | 対応タスク例 | 進化への影響 |
|------------|-------------|-------------|
| 📚 学力 | 宿題・読書・勉強・塾など | 学力50%以上 → 魔術師・賢者系 |
| 💪 体力 | 運動・お風呂・早寝・部活など | 体力50%以上 → 戦士・魔剣士系 |
| 🌿 生活力 | 片付け・お手伝い・食事・早起きなど | 生活力50%以上 → 自然・精霊系 |

### レベル計算
- 学力 ＋ 体力 ＋ 生活力 の合計値 ÷ 10 = レベル（小数点切り捨て）
- 例：学力48 ＋ 体力24 ＋ 生活力18 = 合計90 → Lv.9

### 進化タイミングと進化先

| 状態 | 条件 | 備考 |
|------|------|------|
| 🥚 たまご | スタート時 | |
| 🐣 Lv1 孵化 | 合計10pt | 初日に必ず体験できるよう、親へのタスク設定ガイドで「1タスク最低3pt以上」を推奨 |
| 👾 Lv3 初回進化 | 合計30pt | パラメータ割合で進化先が分岐 |
| 🧿 Lv7 2回目進化 | 合計70pt | より個性が出る中間形態 |
| 😈 Lv15 最終進化 | 合計150pt | 各系統の最強形態 |

※ 進化先は進化タイミング時点の過去30日間パラメータ割合（スナップショット方式）で決まる。

| 割合の傾向 | 進化先（ダークサイド🌑） | 進化先（ライトサイド🌸） |
|------------|------------------------|------------------------|
| 学力50%以上 | 🧙 魔術師・賢者系 | 🦉 賢者・星系 |
| 体力50%以上 | 💀 魔剣士・鬼将軍系 | 🐯 元気・炎系 |
| 生活力50%以上 | 🐺 森の魔王系 | 🦊 妖精・花系 |
| 3つ均等（各25〜40%） | 👑 真の魔王（隠し進化） | 🌟 虹色の精霊（隠し進化） |

## 4. タスク設計（MVP版）

### MVPで扱うタスクの種類
**定期タスクのみ。スポットタスクはフェーズ2。**

| 種類 | 作成者 | 承認フロー | 用途 |
|------|--------|-----------|------|
| 定期タスク | 親 | 完了承認のみ（毎日自動出現） | 毎日の習慣（宿題・お風呂・片付けなど） |

### 写真添付設計

| 項目 | 仕様 |
|------|------|
| 設定者 | 親がタスクごとにオプションで設定 |
| 子どもの体験 | 写真添付できる場合はカメラアイコンが表示される |
| ポイントへの影響 | **ボーナスなし**（写真目的のズル写真を防ぐため） |
| 写真の扱い | 達成記録として図鑑・カレンダーに蓄積される |
| 承認への影響 | 写真必須タスクは写真なしだと承認ボタンが押せない |

**写真が撮れないタスクの例**（親が写真不要に設定する）
- 早寝した
- 野菜を食べた
- 気持ちを落ち着けた

### 権限の分担

| 権限 | 子どもができること | 親ができること |
|------|------------------|---------------|
| タスク内容 | 閲覧のみ | 作成・編集・削除 |
| カテゴリ | 閲覧のみ | 学力・体力・生活力を設定 |
| ポイント（値） | 閲覧のみ | 何点にするか設定（推奨：3〜10pt） |
| 写真添付 | 撮影・添付 | 必須にするかどうかを設定 |

## 5. モンスター図鑑（Must）

「眺めるのが好き」という特性を活かす。図鑑はモンスター画面に統合する。

### 図鑑に載せるもの

| コンテンツ | 内容 |
|-----------|------|
| 現在のモンスター | 今の姿・名前・レベル・パラメータ |
| 進化の記録 | たまご→幼体→現在の変化履歴 |
| 獲得した称号一覧 | ストリーク達成などで解放された称号 |
| 写真つき達成の記録 | 頑張った証拠が時系列で並ぶ |

### カレンダー達成記録（フェーズ2）
- 1ヶ月以上のデータが蓄積されてから意味をなすため、フェーズ2に移動
- イメージ：Githubのコントリビューショングラフ。タスク達成数で色が濃くなり、タップすると写真が見える
- モンスター画面に統合する予定

## 6. ストリーク設計

| 項目 | 仕様 |
|------|------|
| 達成条件 | 定期タスクを1個以上こなす（親に承認してもらう） |
| 途切れたとき | 現在のストリークはリセット。過去の記録・最高記録は残る |
| 表示する数値 | 現在の連続日数 ／ 今月の達成日数 ／ 最高記録 |
| 休息券 | 週1回使えるノーカウント日 |

### ストリーク報酬

| 連続日数 | 称号 | ボーナスpt |
|---------|------|----------|
| 3日連続 | 「はじめの一歩」🔥 | +5pt |
| 7日連続 | 「一週間の戦士」⚔️ | +10pt |
| 30日連続 | 「月の修行者」🌙 | +20pt |
| 100日連続 | 「伝説の冒険者」👑 | +30pt |

## 8. 親子のUXフロー

### 子どもの1日の流れ
1. 朝：アプリを開く → 今日のクエスト確認（**通知ではなく習慣的に開く設計**）
2. 日中：タスクをこなして完了申告 → 写真があれば添付 → パラメータが仮反映
3. 夜：親が承認 → パラメータ確定 → モンスターが光る演出

### 親のUX設計
**「親がめんどくさいと感じた瞬間、アプリは死ぬ」。承認フローは1タップで完結。**

| 機能 | 設計方針 |
|------|---------|
| 承認画面 | タスク一覧 ＋「まとめて全承認」ボタンが最重要 |
| 写真確認 | 写真必須タスクは写真がサムネイルで表示される |
| 差し戻し | やさしいテンプレートコメント必須（「却下」「失敗」は使わない） |
| タスク管理 | Webで管理（スマホブラウザ対応） |
| 通知 | メール通知（プッシュ通知はフェーズ2） |

### タスク締め切りと自動承認

| 項目 | 仕様 |
|------|------|
| タスク締め切り時刻 | 親が家族ごとに設定（デフォルト21時） |
| 自動承認タイミング | タスク締め切りから2時間後 |
| 子どもへの結果反映 | 翌朝アプリを開いたときにバナー表示 |
| 親への通知 | メール通知（承認忘れ防止） |

## 10. 技術スタック

| レイヤー | 技術 | 理由 |
|---------|------|------|
| Web（親・子ども） | Next.js (App Router) + Vercel | 即デプロイ・一人開発に最適 |
| DB・認証・リアルタイム | Supabase | Auth・Realtime・Storageが全部入り |
| リアルタイム反映 | Supabase Realtime | 承認→即座に子ども画面に反映 |
| 写真ストレージ | Supabase Storage | 完了申告の写真保存 |
| メール通知 | Supabase Edge Functions + Resend | シンプルに実装可能 |
| モバイル（フェーズ2） | Expo (React Native) | Next.jsと知識共有 |
| プッシュ通知（フェーズ2） | Expo Push Notifications | iOS/Android両対応 |

### DBスキーマ（概略）
- families（家族グループ・家族コード・締め切り時刻）
- users（親・子どもアカウント・サイド選択）
- tasks（定期タスク・カテゴリ・ポイント・写真必須フラグ）
- completions（完了申告・写真URL）
- approvals（承認・差し戻し）
- parameters（学力・体力・生活力の累計）
- streaks（ストリーク記録・最高記録）

### ⚠️ 絶対に削ってはいけないもの
**「承認したら即座に子どもの画面に反映される」リアルタイム性**

## 11. 開発スケジュール（3フェーズ構成）

### フェーズA：ゲーム要素の検証（Day1〜10）
目標：**子どもが毎日アプリを開くか確認する**

| 期間 | やること | ゴール |
|------|---------|--------|
| Day 1〜2 | Supabase設定・認証・家族コード紐付け | 親子アカウントでログインできる |
| Day 3〜4 | タスクCRUD・タスク一覧画面 | 親がタスクを作れる・子が見られる |
| Day 5〜6 | 完了申告フロー・写真添付 | 子どもが申告できる |
| Day 7〜8 | モンスタービジュアル・図鑑画面 | 眺められるものがある |
| Day 9〜10 | パラメータ仮反映・UI整理 | 子どもに見せられる品質 |
| **Day 11〜** | **フェーズAβテスト開始（2週間）** | DAU・図鑑閲覧回数を計測 |

### フェーズB：承認フローの検証（Day11〜 βテスト結果次第）
目標：**親の承認が子どもの継続率を上げるか確認する**

| やること | ゴール |
|---------|--------|
| 承認画面・まとめて全承認 | 親が1タップで承認できる |
| 承認→リアルタイム反映・モンスター演出 | 承認の即時フィードバック |
| メール通知（承認忘れ防止） | 親の承認率70%以上 |
| パラメータ確定・ストリーク計算 | 数字が正しく積み上がる |

### フェーズC：ズル防止の検証（1ヶ月以降）
目標：**Habiticaで起きたようなズルが防がれているか確認する**

| やること | 確認方法 |
|---------|---------|
| 写真必須タスクの運用確認 | 親へのヒアリング |
| 承認の形骸化チェック | まとめて全承認の使用頻度ログ |
| 子どものズル傾向の観察 | 定性ヒアリング |

## 13. 主要リスクと対策

| リスク | 内容 | 対策 |
|--------|------|------|
| フェーズAで離脱 | モンスターへの愛着が生まれず毎日開かない | ビジュアルクオリティを妥協しない・図鑑を充実させる |
| 親承認の形骸化 | まとめて全承認で写真を確認しない | 写真必須タスクは承認前にサムネイル表示を強制する |
| 承認待ちのストレス | 子どもが申告しても反映されず離脱 | 仮反映＋自動承認で体験を守る |
| ビジュアルクオリティ不足 | モンスターが魅力的でなく愛着が生まれない | AI生成で早期検証・フェーズ2でイラストレーター検討 |
| 1ヶ月後のズル | 熱が冷めた頃に抜け穴を探し始める | フェーズCで観察・都度塞ぐ |
| 作りすぎて詰む | フェーズAに機能を詰め込みすぎる | Day10までに子どもに見せられなければ機能を削る |
