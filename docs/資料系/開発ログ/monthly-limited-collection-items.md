# 月限定コレクションアイテム 設計書

作成日: 2026-07-21
状態: **完全未実装**

## 1. 目的

宝箱コレクションアイテム（現在: 春夏秋冬 × 20種 = 80種、`src/lib/collectionItems.ts`）に、**月ごとの限定アイテムを各5個（計60種）** 追加する。

- 「今月しか出ない」アイテムで宝箱を開ける動機・クエストをこなす動機を強化する
- 取り逃すと翌年まで待ちになるため、コレクションの長期継続フックになる
- 「ほうせき」枠は毎月の誕生石にし、「自分の誕生月の石を狙う」という個人的な目標を作る

### 数の整理

| | 現状 | 追加後 |
|---|---|---|
| 1シーズンあたり | 20種 | 20種（通常） + 15種（月限定 5×3ヶ月） = 35種 |
| 全体 | 80種 | 140種 |
| 月限定のレア度構成（各月） | — | COMMON 2 / UNCOMMON 2 / RARE 1 |

※ 当初「各シーズン +20個」の要望だったが、「月5個 × 3ヶ月 = 15個/シーズン」を採用。
各シーズンちょうど +20 にしたい場合は「季節共通の通常アイテムを +5」を別途追加する（→ §9 未決事項）。

## 2. アイテム一覧（60種）

- 説明文は既存トンマナ（ひらがな多め・短く・ちょっとワクワク）に合わせる
- 「ほうせき」は毎月その月の**誕生石**
  - 6月は本来の誕生石どおり**真珠**とする。既存の夏アイテム `summer-11`「真珠」と重複するため、**`summer-11` を「アレキサンドライト」に改名する**（→ §2.1）
- 上記の改名を前提に、既存80種との名前重複なし。10月にランタンを置かないのは既存の秋 RARE「星月夜のランタン」との被り回避

6月の誕生石を真珠にするため、既存の夏「ほうせき」UNCOMMON を差し替える。

## 3. データモデル

### `src/lib/collectionItems.ts`

```ts
export interface CollectionItem {
  id: string;
  season: CollectionSeason;
  category: CollectionCategory;
  rarity: CollectionRarity;
  name: string;
  description: string;
  image: string;
  /** 月限定アイテムのみ設定 (1〜12)。通常アイテムは undefined */
  month?: number;
}
```

- ID 規約: 月限定は `m{MM}-{NN}`（例: `m07-03`）。既存の `{season}-{NN}` とは衝突しない
- `season` は月から一意に決まる（3-5月=spring / 6-8月=summer / 9-11月=fall / 12-2月=winter）ため、月限定アイテムにも必ず設定する。既存の `getItemsBySeason` / シーズンタブ集計がそのまま機能する
- 追加ヘルパー:
  - `getMonthlyItems(month: number): CollectionItem[]` — その月の限定5個
  - `getMonthForDate(date: Date): number` — JST 基準の月（`getSeasonForDate` と同様に JST オフセットで判定）
- 画像: `public/collection-items/monthly/{名前}.webp`。未制作の間は `DUMMY_IMAGE` を使用（→ §8.1 の差し替えタスク）

### DB

**スキーマ変更なし。** 所持実績は既存の `UserCollectionItem`（`itemId` + `season` 文字列）にそのまま保存する。マスターはコード管理のため月情報も `itemId` から引ける。

## 4. 抽選ロジック（`treasureService.openOldestTreasure`）

現状: 親ごほうび不当選時に `getItemsBySeason(getSeasonForDate(now))` の20個から `drawCollectionItem` で抽選。

変更後:

```
プール = 現在シーズンの通常20個 + 現在月（JST）の限定5個 = 25個
```

- `drawCollectionItem` のレア度バケット（RARE 10% / UNCOMMON 30% / COMMON 60%、同ティア内は等確率）は**変更しない**
- 月限定はティア内の頭数で自然に出る（例: COMMON を引いたとき 12個中2個が月限定 ≒ 月限定 COMMON の実効出現率は約10%）
- 月の境界は JST 月初 0:00（シーズン境界と同じ規約。`src/lib/date.ts` / JST オフセット方式に従う）

### 表示ルール

1. **「今月のげんてい」ピン留め**: 現在シーズンのタブを開いたとき、最上部に今月の5個と「のこり◯日！」（JST 月末までの残日数）を表示。子供が開いた瞬間に「今月はこれ、あと◯日」が見えることが最重要
2. **過去月の未入手**: シルエット＋「また来年！」
3. **未来月**: シルエット＋「◯月になったらとうじょう！」（名前は「？？？」のまま）
4. **カウンター分離**: シーズン計を「つうじょう 12/20 ・ 月げんてい 3/15」の2本立てにする。全体計も「ぜんぶで 45/80 ＋ げんてい 9/60」のように分ける（母数が急増して達成感が目減りするのを防ぐ）
5. **詳細モーダル**: 「夏 / たべもの / ★★」の並びに「7月げんてい」チップを追加
6. NEW バッジ・所持数 ×N・レア度枠色は既存仕様のまま月限定にも適用

### 開封演出

宝箱開封結果で月限定を引いた場合、獲得表示に「✨◯月げんてい✨」のリボン/ラベルを追加する（子供の宝箱ページ、および `OpenedCollectionItem` を表示している箇所）。`OpenTreasureResult.collectionItem` に `month` を含めて返す。

### 親画面（child-view）

`ItemsContent` を fetchUrl 違いで再利用しているため**子供側の実装がそのまま反映される。追加作業なし**。

## 6. API 変更

`/api/collection-items`（および `/api/parent/child-view/collection-items`）のレスポンス:

- `items[]` に `month?: number` を追加
- ルートレベルに `currentMonth: number`（JST）を追加（クライアントの「今月」「のこり◯日」判定用。残日数はクライアントで JST 計算してもよいが、月判定はサーバと揃えること）

## 7. バッジへの影響（重要）

バッジ判定（`src/lib/badges.ts`）は `ALL_COLLECTION_ITEMS` を動的参照しているため、**何もしないと以下が壊れる**:

| バッジ | 現状 | 60個追加後（対策なしの場合） |
|---|---|---|
| `season_complete`（1シーズン20種制覇） | 20種 | 35種（月限定込み。取り逃すと最長1年待ち）に暴騰 |
| `item_80_all`（全80種制覇） | 80種 | 140種に暴騰 |

**対策: バッジ判定は通常アイテムのみを対象にする（`month` が無いものでフィルタ）。**

- `collectionSeasonsComplete` / `hasAllCollectionItems` の算出時に `ALL_COLLECTION_ITEMS.filter(i => i.month === undefined)` を母数にする
- `collectionItemCount`（item_first / item_30）は月限定も数えてよい（累積カウントなので害がない）
- 月限定コンプ系の新バッジ（例:「◯月コンプ」「誕生石12個」）は本仕様のスコープ外。badge-redesign と合わせて別途検討
