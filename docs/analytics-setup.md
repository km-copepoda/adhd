# アナリティクス導入 仕様書

作成日: 2026-05-29

## 目的

親と子供が実際にどのページをどの程度使っているかを可視化する。
アンケートでは拾えない無意識の行動パターンを把握し、機能の優先順位判断に使う。

---

## 1. ツール選定

**Vercel Analytics** を採用する。

| 項目 | 内容 |
|------|------|
| ツール | Vercel Web Analytics（`@vercel/analytics`） |
| 費用 | Hobbyプランに含まれる（無料） |
| Cookie | 不要（同意バナーなし。子供向けアプリとして適切） |
| PII | 収集しない |
| 導入コスト | パッケージ追加 + 1行のコンポーネント追加で完了 |

### 選定理由

- MVPの段階では「どのページが見られているか」が分かれば十分
- Cookie不要なので子供向けアプリのプライバシー面で安全
- Vercelにデプロイ済みのため追加設定がほぼ不要
- ファネル分析・コホート分析が必要な段階になったら GA4 や PostHog に移行する

---

## 2. 見たい指標

### ページ別

| 観点 | 知りたいこと |
|------|-------------|
| 親画面のページビュー | 承認ページ以外が使われているか？タスク設定ページの利用頻度は？ |
| 子供画面のページビュー | クエスト以外のタブ（育成・宝箱・ひろば・コレクション）はどの程度見られているか？ |
| 親 vs 子供の比率 | 親が積極的に使っているか、放置しているか |
| ほとんど見られていないページ | 削除・統合の候補になる |

### 活用例

- 「承認ページしか開かれていない」→ 親の関与が薄い。週次レポート等で接点を増やす必要あり
- 「タスク設定の滞在時間が長い」→ UIが分かりにくい可能性。改善の優先度を上げる
- 「育成ページのPVが高い」→ モンスター育成が刺さっている裏付け
- 「ひろばのPVが低い」→ ソーシャル機能の訴求方法を見直す

---

## 3. 導入手順

### ステップ1: パッケージ追加

```bash
npm install @vercel/analytics
```

### ステップ2: コンポーネント追加

`src/app/layout.tsx`（ルートレイアウト）に追加:

```tsx
import { Analytics } from '@vercel/analytics/react';

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        {children}
        <Analytics />
      </body>
    </html>
  );
}
```

### ステップ3: デプロイ

Vercelにデプロイすれば自動的にダッシュボードでデータが見られる。
ローカル開発環境では計測されない。

---

## 4. 将来の移行判断

以下の段階になったら、より高機能なツールへの移行を検討する：

| 段階 | 必要な分析 | 移行先候補 |
|------|-----------|-----------|
| ユーザー100家庭超 | ファネル分析（どこで離脱するか） | PostHog（無料枠: 月100万イベント） |
| 有料プラン検討時 | コホート分析・課金転換率 | GA4 or Amplitude |
| 広告出稿時 | アトリビューション | GA4 |

MVPの現段階ではVercel Analyticsで十分。過剰な計測は入れない。
